# 문제 해결

`bay doctor`로 시작한다. 머신 설정을 보고하고 아무것도 바꾸지 않는다.
`bay status`는 무엇이 실행 중인지 보고한다.

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 이름이 해석되지 않는다 | DNS 에이전트가 등록되지 않았다 | `bay install` |
| 에이전트가 등록됐는데도 해석되지 않는다 | 프록시가 없는 동안의 응답이 캐시됐다 | 몇 초 뒤 다시 시도 |
| 프록시가 502를 반환한다 | 컨테이너는 실행 중이나 해석된 포트를 듣지 않는다 | `bay logs <서비스>` 후 `bay schema`의 포트 순서 확인 |
| 프록시가 404를 반환한다 | 그 이름을 가진 라우트가 없다. 서비스가 정지했거나 internal이거나 도메인이 다르다 | `bay status` |
| 라우트가 있는 이름에 인증서 경고 | 인증 기관이 신뢰되지 않았다 | `bay install` |
| 라우트가 없는 이름에 인증서 경고 | 상위가 라벨 하나인 와일드카드는 클라이언트가 거부한다 | `shop.test`처럼 라벨 두 개인 도메인 사용 |
| 명령이 암호를 묻는다 | 프로젝트가 아직 위임되지 않은 도메인을 쓴다 | 정상. 도메인마다 한 번 묻는다 |
| 고친 뒤에도 브라우저만 실패한다 | 브라우저가 인증서를 캐시했다 | 새 창을 연다 |

## 다른 프로그램에서 상태 읽기

```sh
bay status --json
```

머신 상태, 등록된 모든 프로젝트, 서비스별 상태와 주소, 인증서 목록을 담는다.

## 프록시가 없을 때

프록시는 라우트를 만드는 명령이 생성하고, 마지막 라우트가 회수되면 제거된다.
아무 프로젝트에서 `bay up`을 실행하면 다시 생성된다.

## 전부 제거

제거 절차는 `docs/operations/install.ko.md`에 있다.
